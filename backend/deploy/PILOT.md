# Single-school production pilot

The public HTTPS hostname and Meta account are external setup. A raw IP or a token alone cannot activate delivery. The repo includes a Caddy reverse proxy example and separate systemd units for the API and the report worker.

1. Provision PostgreSQL 17+ and a database owner plus the restricted runtime role described in [the database setup](../README.md). Run `python backend/scripts/migrate.py` with the owner URL from a trusted shell. Use the restricted `DATABASE_URL` for both running services. Use TLS with certificate verification for a remote database.
2. On the Linux host, put the checkout at `/opt/parentreport`. Create `backend/.venv` and install `backend/requirements.txt`. Build the frontend with `npm run build` from `frontend/` and copy the contents of `frontend/dist/` to `/srv/parentreport`. Point DNS at the host and configure Caddy with the supplied Caddyfile. Substitute `PARENTREPORT_HOST` with the public hostname or set that variable in Caddy's service environment. Keep the API bound to loopback.
3. Set up a dedicated `parentreport` OS service user and an administrator-only `/etc/parentreport/runtime.env`. Set `APP_ENV=production`, `APP_ORIGINS=https://your-hostname`, the runtime database URL, and `APP_LOCAL_ONBOARDING=false`, `APP_LOCAL_RECOVERY=false`. Provision the first school admin through school registration and then close registration with `APP_SCHOOL_REGISTRATION=false`. Retrieve the pilot school ID from the authenticated `/api/v1/schools` response.
4. Complete the [Meta test-message and callback setup](../WHATSAPP.md). Run the explicit test command for your verified recipient and confirm receipt on the phone. Check the public callback URL in Meta. Before adding any real guardians, set and securely back up the Fernet `ONBOARDING_KEY`. Configure the pilot school ID, Meta sender, token, approved templates and webhook secrets. Set `APP_WHATSAPP_LIVE=true` and install/start the included API and worker units. Keep the migration owner URL out of the runtime environment.
5. Use one test student and guardian first. Issue an invitation, verify by WhatsApp OTP, record consent, publish a report, and queue the notification. Confirm the guardian receives the notification and the status updates in the portal. Verify that withdrawing consent prevents a second report notification and that a guardian cannot see another student's reports. Add real recipients after this check passes.

Monitor HTTPS `/health`, service restarts, and the live delivery counts. Use your PostgreSQL backup service or schedule encrypted `pg_dump -Fc` backups to separate storage and test restoring into an isolated database. Back up the contact encryption key separately. Restrict access to application and proxy logs and omit webhook query strings. To stop outbound notifications, stop the worker service. To close new live queues and OTP requests, set `APP_WHATSAPP_LIVE=false` and restart the API.
